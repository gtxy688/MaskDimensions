## 〇、为什么写这份文档

本文档不只是"改什么"，而是**每个技术决策都解释清楚**：

1. **X 是什么** —— 我们选的技术/方案是什么，用大白话讲；
2. **Y 是什么** —— 被否掉的替代方案是什么，为什么它不行或不够好；
3. **为什么选 X** —— 选型的真实理由（面试叙事、工程正确性、工作量）。

这份文档是作者（新手）的"为什么手册"，也是面试前复习的提纲。每一节的技术点都对应一个"面试官会深挖 30 分钟"的问题。

## 一、现状盘点（改造前的事实）

### 1.1 项目当前状态（来自 git log 与代码审查）

- 开发周期：2026-05-19 ~ 2026-06-17，约一个月，之后无提交（截止 8/24）。
- 玩法：2D 平台跳跃 + 表/里世界（面具）切换 + 理智资源限制 + 弹幕关卡，共 3 关。
- 技术现状：
  - 玩家用 **Rigidbody2D**（动态刚体）驱动，`OverlapBox` 检测地面，`Physics2D.IgnoreLayerCollision` 切换维度碰撞。
  - 已有一套**自研射线运动学物理控制器**（`RaycastController2D` + `PlayerPhysicsController2D`，带斜坡/单向板），**但从未被引用，是死代码**（疑似教程遗留）。
  - 泛型对象池 `ObjectPool<T>` 实现质量较高（Prewarm / 容量上限 / 防重复入池），但解决的是本项目并不存在的 GC 压力问题（"为简历而写"的痕迹）。
  - 状态机（Idle/Move/Jump/Fall/Hit/Die/MaskSwitch）+ 字典注册表，质量中规中矩。
  - 渲染：已启用 URP，但残留旧版 `com.unity.postprocessing`（PPv2），双后处理体系并存。

### 1.2 与"秋招旗舰"的差距

| 维度 | 现状 | 目标 |
|---|---|---|
| 技术深度 | 每样都做了，没有一样打穿 | **一个点做到大多数应届生做不到**（自研物理） |
| 差异化 | 无（与只狼项目重叠在动画/框架层） | 2D 确定性物理 + 渲染差异化，与 3D 战斗错位互补 |
| 叙事 | "术语清单"式，教程痕迹明显 | 从零自研，第一性原理可推导 |
| 内容 | 3 关，机制单薄 | 3 关围绕新能力重做，每关一个教学主题 |

### 1.3 改造总原则

- **双线并进**：物理线（自研运动学控制器）+ 渲染线（后处理/2D 光照/Renderer Feature）。
- **完成度档次 A**：面试深度优先，不做测试/CI 等重工程层（YAGNI）。
- **关卡全部重做**，旧 3 关作废。
- **清理所有"教程痕迹"和死代码**，让叙事干净。

## 二、物理线：自研运动学物理框架（核心差异化）

### 2.1 决策：从零重写，而非复活旧代码

- **X 是什么（我们选的）**：从零设计一套运动学物理框架 `Kinematic2D`，删掉旧的 `RaycastController2D` / `PlayerPhysicsController2D`。玩家彻底告别 Rigidbody2D。
- **Y 是什么（被否的）**：
  - Y1 = 复活旧代码（它已有斜坡/单向板，补全后接入玩家即可）；
  - Y2 = 保留 Rigidbody2D，物理线只做"演示场景"。
- **为什么选 X**：
  1. 旧代码是经典教程结构（Sebastien Lague 风格），面试官可能一眼认出 → "自研"叙事破产；
  2. 从零写逼作者真正吃透碰撞迭代、斜坡换算、单向板规则 → 面试被追问时能推导而不是背诵；
  3. Y2（保留 Rigidbody2D）无法实现"射线级维度过滤"这个核心叙事（见第三节）。
- **代价**：工期最长、手感调试成本高。**接受**，因为它是本项目的招牌。

### 2.2 框架结构

```
Assets/Scripts/Kinematic2D/
├── KinematicBody.cs          # 核心：每帧位移求解 + X/Y 分离碰撞迭代
├── ICollisionFilter.cs       # 可注入碰撞过滤接口（维度切换入口）
├── CollisionResult.cs        # 碰撞结果（IsGrounded / 四向标志 / 命中信息）
├── ColliderMapping.cs        # BoxCollider2D 几何 → 射线原点映射
├── RayConfig.cs              # SkinWidth / 射线密度 / 间距配置
└── ===== 增量模块（核心稳定后按 YAGNI 逐个加）=====
    ├── SlopeResolver.cs      # 斜坡换算（爬坡/下坡）
    ├── OneWayPlatform.cs     # 单向板穿透规则
    └── MovingPlatform.cs     # 移动平台跟随
```

### 2.3 核心设计：X/Y 分离碰撞迭代（Move & Slide）

- **X 是什么（我们选的）**：每帧把 `velocity * dt` 拆成 **X 方向移动 → 检测 → 修正**、**Y 方向移动 → 检测 → 修正** 两步，分轴处理。
- **Y 是什么（被否的）**：一次性算出完整 `moveAmount` 再 `transform.Translate`（旧代码的做法）。
- **为什么选 X**：
  1. **分离轴处理**：X 与 Y 互不干扰，对角线移动不会穿墙（一次位移 + 一次斜对角检测容易同时擦过两个面）；
  2. 每轴独立修正，逻辑简单、可单测、面试好讲（"为什么分两次？因为碰撞本质是分离轴问题"）；
  3. 为斜坡/单向板/移动平台留了干净的插入点。

### 2.4 关键配置

| 参数 | 值 | 说明 |
|---|---|---|
| SkinWidth | 0.015f | 防止浮点误差导致的穿透与卡缝（沿用已验证的经验值） |
| 水平射线数 | 4 | 与垂直方向均匀分布，覆盖碰撞盒 |
| 垂直射线数 | 4 | 同上 |
| 最大爬坡角 | 60° | 超过视为墙 |
| 最大下坡角 | 60° | 同上 |

### 2.5 玩家接入方式

- `PlayerController` 保留职责（输入轮询 + 状态机 + 面具逻辑），底层替换：
  - 删除所有 `RB.velocity` 赋值 → 改为 `kinematicBody.Move(velocity)`；
  - 地面检测从 `Physics2D.OverlapBox` + "双重世界排除" hack → 直接读 `CollisionResult.IsGrounded`；
  - 顿帧 / 预览 / 时间缩放逻辑不动（它们与时间系统耦合，与物理无关）。
- 手感参数（土狼时间/跳缓冲/加速度）继续由 `PlayerConfigSO` 驱动，物理层**不碰输入**，只做位移求解。

## 三、维度系统重构：从"全局开关"到"射线级过滤"

### 3.1 决策

- **X 是什么（我们选的）**：`KinematicBody` 的每条射线命中后，先经过一个可注入的 `ICollisionFilter`——"这个物体在当前维度可见吗？"不可见则无视这次命中。维度过滤从"物理引擎的全局状态"下沉为"单个角色的射线视野"。
- **Y 是什么（被否的）**：
  - Y1 = 保留 `Physics2D.IgnoreLayerCollision`（现方案）：修改的是**物理引擎的全局静态开关**，影响场景里所有同层物体，不止玩家；
  - Y2 = 继续用 OverlapBox + 命中后手工按 layer 过滤（现方案的"双重世界排除"补丁）。
- **为什么选 X**：
  1. **精确**：只影响自己这条射线，不影响其他系统（多角色/多关卡不互相污染）；
  2. **可扩展**：如果做双人/多人，每个角色注入自己的过滤器即可（面试经典问题"双人怎么办"有干净答案）；
  3. **叙事统一**：碰撞逻辑和维度逻辑在一个地方，删掉两层 hack。
- **旧方案的问题（记录）**：IgnoreLayerCollision 是全局静态；OverlapBox 检测完再手工排除 = 物理引擎不知道你在干嘛，补丁叠补丁。

### 3.2 保留 / 移除清单

| 项 | 处理 | 原因 |
|---|---|---|
| `MaskObject` 显隐逻辑（OnEnable/OnDisable + Renderer.enabled） | ✅ 保留 | 已正确，解决池复用状态残留 |
| `Physics2D.IgnoreLayerCollision` | ❌ 删除 | 被 ICollisionFilter 取代 |
| `OverlapBox` 地面检测 + 双重排除 | ❌ 删除 | 改读 CollisionResult |
| 静态事件（OnMaskStateChanged 等） | ✅ 保留（单人合理） | 但状态持有者改为可注入 `WorldState` 对象，替代裸静态字段 |
| 静态全局 `IsMaskActiveGlobally` | ⚠️ 改造 | 移入 WorldState 实例，面试可讲"双人时实例化即可" |

## 四、渲染线：三条差异化视觉

> 铺垫概念（新手向）：
> - **后处理（Post Processing）**：画面渲染完后再叠一层滤镜/特效（色调、噪点、扫描线、扭曲）。类比：拍照后的滤镜。
> - **2D 光照（URP 2D Light）**：给 2D 精灵加真实光照/阴影（法线贴图、光源遮挡）。类比：舞台灯光师。
> - **Renderer Feature**：往 URP 渲染流程里"插一段自己的处理"（自定义工序）。类比：流水线加一道工序。
> - **Volume**：URP 的后处理容器，放一堆滤镜并控制混合过渡。类比：滤镜包 + 混音台。

### 4.1 决策 0：移除 PPv2，统一到 URP Volume

- **X 是什么**：删掉 `com.unity.postprocessing` 3.4.0（PPv2），全部后处理用 URP 原生 Volume 体系。
- **Y 是什么**：保留 PPv2（项目现状：两套后处理并存）。
- **为什么选 X**：URP 的 Volume 与 2D Light、Renderer Feature 是同一生态，统一才有后续；PPv2 是上一代方案，与新管线并存会双份后处理叠加、兼容 bug、面试被问"为什么两套"很难答。

### 4.2 线 1：世界差异化后处理（Volume 系统）

- **做什么**：表世界一个 Volume（冷色调、清朗、轻微暗角）；里世界另一个 Volume（噪点、扫描线、色差/扭曲、更暗）。切换瞬间两个 Volume 的 **weight 交叉淡化**，配合顿帧形成"断片"感。
- **X vs Y**：X = Volume weight 动态过渡（有动画、可讲故事）；Y = 每世界一套相机设定硬切（无过渡、视觉张力差）。
- **面试点**：Volume weight 怎么驱动过渡？→ 切换协程里用 `Time.unscaledDeltaTime` 驱动两个 Volume 的权重插值。

### 4.3 线 2：2D 光照差异化（URP 2D Light）

- **做什么**：表世界全局明亮 + 玩家持光源（手持灯）；里世界全局昏暗 + 局部光源 + 色温改变。
- **X vs Y**：X = URP 2D Light（真实光照计算，需法线贴图等素材，层次感强）；Y = 只调后处理亮度（假光，无遮挡感）。
- **面试点**：为什么里世界要有自己的光？→ 光照差异是"危险程度"的视觉语言，承载信息（见 4.5）。

### 4.4 线 3：自写 Renderer Feature（shader 功底）

- **做什么**：自写一个自定义效果——**维度切换扫屏转场**（屏幕撕裂/展开切换到另一世界）或**里世界描边**（inverted hull）。
- **X vs Y**：X = 自写 Renderer Feature + Shader（展示 ScriptableRenderPass 与 shader 功底，大厂吃这套）；Y = Asset Store 现成转场插件（省事但无技术含量）。
- **面试点**：ScriptableRenderPass 的生命周期、CommandBuffer 的用法、为什么需要额外相机/全屏 Pass。

### 4.5 视觉语言设计（渲染服务玩法）

- 表世界 = 冷色、清朗、明亮 → "安全"
- 里世界 = 暖暗、噪点、扫描线 → "危险但有机遇"
- 两个世界的视觉差异本身就是关卡信息（玩家靠颜色判断危险），渲染线因此**不是装饰，是玩法的一部分**。

## 五、关卡重做设计

### 5.1 设计原则

**每个机制在关卡里必须有一个"只能靠它才能过"的瞬间**——不是"用了更爽"，而是"不用过不去"。

必须被秀出的技术点：
1. 自研物理 → 斜坡冲刺、单向板下穿、动量继承（切世界不掉速）
2. 维度切换 → 表/里结构不同的同一条路
3. 渲染 → 颜色即信息（危险/安全）

### 5.2 关卡结构

| 关卡 | 主题 | 核心教学 | 秀的技术点 |
|---|---|---|---|
| L1「表里初现」 | 维度切换教学 | 里世界才有的桥 / 表世界才有的墙，被迫来回切 | 维度切换 + 切换瞬间视觉冲击 |
| L2「斜坡法则」 | 斜坡 + 动量 | 长斜坡冲刺跳、下坡加速跳远、单向板上下穿 | 斜坡换算、单向板规则、动量继承 |
| L3「断章」 | 综合 + 理智压力 | 里世界限时通道（理智耗尽强制弹回）+ 连续切换解谜 | 全部：物理 + 维度 + 视觉 + 理智压迫 |

每关结构：**教学段（安全试错）→ 应用段（机制组合）→ 挑战段（限时/密集）**。

### 5.3 数据驱动（升级版）

- 每个房间一个 `RoomConfigSO`：弹幕参数、维度要求（强制表/里）、理智消耗倍率。
- 关卡顺序/传送点仍由场景中的 `RoomTrigger` 配置；SO 只存参数——**保持"代码与数值隔离"，且这次是玩法真正需要**（区别于"为写而写的对象池"）。

### 5.4 明确不做（YAGNI）

- ❌ 收集品 / 成就 / 商店（内容系统，与"秀技术"无关）
- ❌ 多存档 / 设置页重做（现有 UI 够用）
- ❌ Boss 战（那是只狼项目的领域；本项目的差异化在物理与视觉）

## 七、架构总览（改造后）

```
GameScene
├── Player（Rigidbody2D → KinematicBody）
│     ├── PlayerController（输入 + 状态机 + 面具逻辑）
│     ├── KinematicBody（自研运动学物理）
│     ├── ICollisionFilter（维度过滤，注入）
│     └── WorldState（维度状态持有者，替代静态字段）
├── MaskObject[]（显隐逻辑保留；供过滤器查询维度标记）
├── Volume_RealWorld / Volume_MaskWorld（后处理差异化）
├── URP 2D Light（双世界光照）
├── Renderer Feature（切换转场 / 描边）
├── RoomTrigger + RoomConfigSO（数据驱动关卡）
└── BulletSpawner + Bullet + ObjectPool<T>（保留）
```

数据流（维度切换瞬间）：
```
玩家输入 J → PlayerController 状态机 → 顿帧（timeScale=0）
  → WorldState 维度翻转 → ICollisionFilter 更新 → MaskObject 显隐刷新（OnEnable/OnDisable）
  → Volume weight 过渡（unscaledDeltaTime）→ 转场 Feature 播放 → 恢复时间
```

## 八、错误处理与边界（面试深挖点）

| 场景 | 处理 |
|---|---|
| 射线命中距离为 0（重叠） | 跳过该次命中，防止除零/抖动 |
| 斜坡角度 > 60° | 按墙处理（不做爬坡） |
| 单向板向上跳跃 | 直接穿透；下落踩中才阻断 |
| 顿帧期间输入 | 缓冲计数不清零（现有行为），需明确这是特性还是 bug，面试时能答 |
| 维度切换瞬间动量 | 物理层不重置速度，动量自然继承（这是卖点，需保证实现） |
| 移动平台 | 由 `CollisionResult.below` 驱动跟随（增量模块） |

## 十一、技术选型速查表（面试/复习用）
