# 面试提纲（interview-prep）

> 用法：每条 = 面试官可能的问题 + 3 句话标准答案（X/Y/为什么的压缩版，能口头复述）。
> X = 我选的方案，Y = 没选的方案，完整论证见 `decisions.md`。最后附真实 bug 的 STAR 故事素材。
> 纪律：**没有实测数据的卖点不主动提**（见 D11），被追问再展开。

---

## 一、12 条决策问答

### D1 玩家物理：为什么不用 Rigidbody2D？

**Q：2D 平台跳跃直接用 Rigidbody2D 不就行了，为什么要自己写物理？**

答：我选自研运动学控制器，是因为平台跳跃是手感行业——土狼时间、跳缓冲这些高级手感，在动态刚体上要靠对抗引擎做 hack（调 gravityScale、锁速度），而自研物理直接读碰撞解算结果就能干净实现。第二个原因是确定性：位移完全由自己的代码决定，没有引擎浮点积分和"撞到东西被弹开"的不可控行为。第三个原因和我的维度系统契合：我自己的射线天然支持"过滤掉另一个维度的命中"，这正是 Rigidbody2D 做起来很别扭的地方。

### D2 物理框架：为什么从零写而不是用现成的？

**Q：网上有很多射线控制器教程，为什么不参考/复用？**

答：项目里原来就躺着一套教程风格的射线控制器（死代码），我删掉重写了。一是那套结构面试官一眼能认出出处，"自研"的叙事当场破产；二是从零写逼我吃透碰撞迭代、斜坡换算、单向板规则的第一性原理，被追问时能现场推导而不是背诵；三是新 API 是为维度过滤量身设计的（过滤器注入），教程代码没有这个概念。

### D3 维度碰撞：为什么不用 IgnoreLayerCollision？

**Q：切换世界让两个 Layer 不碰撞，一个 API 的事，为什么绕开它？**

答：`IgnoreLayerCollision` 是全局静态开关，影响场景里所有物体而不是只影响玩家，多角色多关卡时容易互相污染；而且它是"状态"不是"查询"，改完之后代码想确认"现在谁和谁不碰"得去读全局配置。我的 `ICollisionFilter` 是射线级的局部判断——每条射线命中后问一句"这个物体在当前维度可见吗"。最关键的扩展题：**如果做双人模式怎么办**——全局开关直接崩（一个玩家在表世界一个在里世界），我的方案每个玩家注入自己的过滤器就行。

### D4 地面检测：为什么读碰撞结果而不是 OverlapBox？

**Q：地面检测画个 OverlapBox 不就完了？**

答：OverlapBox 是"补丁叠补丁"——查完物理引擎还要按 layer 手工排除另一个维度，逻辑散落两处。我直接读物理层解算出的 `CollisionResult.IsGrounded`：站斜坡、站单向板、站移动平台，地面事实都来自同一套射线系统，天然一致，不需要每种情况写特判。检测和运动用的是同一份真相，不会出现"物理说没撞但检测说有地"的分裂。

### D5 后处理：为什么 URP Volume 而不是 PPv2？

**Q：后处理为什么统一到 Volume？**

答：项目已经启用 URP，PPv2 和 URP 并存会有双份后处理互相干扰的风险。我的渲染三线（Volume 滤镜、2D 光照、Renderer Feature 转场）全部是 URP 生态，统一后三者能在同一套框架里协同——比如切换瞬间 Volume weight 过渡和转场 Pass 同时启动。另外 URP Volume 是 Unity 现行标准，答"为什么统一"比答"为什么两套并存"容易得多。

### D6 世界视觉：为什么双 Volume 而不是改参数？

**Q：切换世界换个滤镜颜色不就行了？**

答：旧实现是单 Volume 用协程 lerp 饱和度曝光，只能改"数值"，表达不了"两套完全不同的视觉风格"——里世界的噪点、扫描线、色差这类需要开关整个组件的差异，双 Volume 的 weight 交叉更干净。这也是 URP 推荐的场景氛围切换做法。实现上有个细节：weight 过渡用 `Time.unscaledDeltaTime` 驱动，所以顿帧（timeScale=0）期间过渡继续播放，不会卡住。

### D7 光照：为什么用 2D Light 而不是后处理调暗？

**Q：里世界变暗，后处理调个曝光不就得了？**

答：后处理调亮度是"假光"——没有明暗层次，只是给全屏套滤镜。我用 URP 2D Light：双 Global Light 做环境光交叉、玩家持点光，配合 Sprite-Lit 材质有真实的光照反应。暗环境 + 噪点滤镜叠加才有"里世界的压抑感"。这套东西也是 URP 特色技术栈，讲得出口。

### D8 转场：为什么自己写 Renderer Feature？

**Q：转场效果用现成插件不行吗？**

答：现成插件没有技术含量，简历写不出亮点。自写 = ScriptableRenderPass + CommandBuffer + 手写 HLSL，这是客户端面试的硬通货。而且转场和维度切换的时机深度耦合（顿帧期间播放、与滤镜过渡同时启动），只有自己写 Pass 才能精确控制插入点（BeforeRenderingPostProcessing）和时机。

### D9 关卡：为什么三关全部重做？

**Q：改造物理为什么要动关卡？**

答：旧关卡是按 Rigidbody2D 手感设计的，换自研物理后跳跃距离、下落速度全变了，硬留旧关等于玩法和物理不匹配。更重要的是关卡是"秀技术"的舞台——我为每个新机制设计了"不用它就过不去"的瞬间：里世界才有的桥、必须靠坡末起跳的沟、理智耗尽就强制弹回的限时通道。三关体量小，重做成本可控，收益是每个技术点都有实战展示。

### D10 工程层：为什么不做测试和 CI？

**Q：这么大的改造，怎么保证质量？**

答：这是秋招作品，我的时间预算优先投给"面试深度"而不是"工程完备度"。验证靠人工验收清单——每个模块交付时附操作步骤+预期结果，在 Unity 里逐条验证后才允许提交。这套流程在这个项目跑了 16 个任务，真实抓出过回归（比如"站定按空格跳不起来"就是验收清单抓出来的状态机 bug）。时间富余的话 CI 随时可以补。

### D11 对象池：为什么保留但不当卖点？

**Q：你有对象池，为什么不讲？**

答：因为本项目子弹量小，根本不存在 GC 压力——对象池在解决一个不存在的问题，面试官一问"你测过 GC 吗"就露馅。我保留它的实现（Prewarm、容量上限、防重复入池，质量确实不错），但叙事上降级为"工程常识"而不是"核心亮点"。要重新启用为卖点，条件是先测出真实数据。

### D12 状态机：为什么不升级 HFSM？

**Q：玩家状态机为什么这么简单？**

答：我有另一个只狼复刻项目专门做 HFSM/战斗深度，两个项目刻意错位——这个项目的差异化在物理与渲染，状态机够用即可。现有实现是字典注册表 + BaseState 生命周期 + 白名单防非法切换，质量可用，为重构而重构违反 YAGNI。面试时这反而是加分项：知道什么东西**不值得**做复杂。

## 二、真实 Bug STAR 故事（讲调试能力）

### 故事 1：穿墙——`Physics2D.SyncTransforms`（S：情境→T：任务→A：行动→R：结果）

- **S**：自研物理验收时，角色 Play 中直接穿过地面掉出场景，坐标一路掉到 y=-49。
- **T**：定位穿墙根因并修复，且不能靠"加厚墙体"这类糊弄手段。
- **A**：用编辑器脚本做射线实验，发现改 `transform.position` 后物理系统的碰撞体 bounds 缓存不更新，下一帧射线从**陈旧位置**发出（实测偏移 0.35 单位），够不到墙。修复：`Move()` 开头调用 `Physics2D.SyncTransforms()` 强制同步。顺带修掉第二个坑：命中后的重叠回退公式写成 `penetration*dir` 会把物体往墙里推，正确公式是 `(distance - skinWidth) * dir`（方向自带，负距离即自动退出重叠）。
- **R**：穿墙消失；这条写进了物理框架的硬约束文档——"改位置后立即射线检测"是全项目都要警惕的模式。

### 故事 2：复合碰撞体内侧隧道

- **S**：出生点和换房后随机掉落到地图底部，被底边框接住。
- **T**：解释为什么只有特定位置掉、其他位置正常。
- **A**：MCP 编辑器实验坐实：地面是 CompositeCollider2D（Outlines 几何），**射线起点位于轮廓内侧时**即使 `queriesStartInColliders=true` 也不报告命中，向下射线直接隧道到对侧底部。修复两层：`MoveVertically` 向下分支前做"脚底上探"（2×skinWidth），贴地表时微上推防隧道；玩家落地时钳制 `Velocity.y=0`，防止站定期间速度累积放大撞击。
- **R**：掉落消失，且把这个引擎级缺陷写进文档，后续任何复合碰撞体关卡都免疫。

### 故事 3：全配对了却零效果——Volume `overrideState` 三层坑

- **S**：维度滤镜配置全部正确（Profile 资产值对、Volume 权重对、事件链路通），但画面零变化；修两轮都无效。
- **T**：找出"静态检查全绿但运行时无效"的真根因。
- **A**：层层下钻到 `VolumeManager.instance.stack` 的合成结果，发现永远是默认值——**Volume 合成只采用 `overrideState=true` 的参数**，而代码创建 Profile 组件时所有参数默认关闭 override，只设 `.value` 是无效的。修复 `SetAllOverridesTo(true)`。过程中还踩了两个伴生坑：Play 模式中改资产不生效（运行时持有的是实例化副本）、以及"验证维度要对"——磁盘上值正确不代表 overrideState 正确，之前两轮"验证全绿"都是假阳性。
- **R**：滤镜生效，并且沉淀出一条方法论：渲染问题的验证必须落到**真正消费数据的那个环节**（这里是 stack 合成），而不是资产层。

### 故事 4：转场 Renderer Feature 四轮调试

- **S**：自写全屏转场 Pass，用户实测依次出现"1/4 屏 → 位置颠倒 → 全白 → 画面上下颠倒"四种症状。
- **T**：逐轮定位渲染链问题。
- **A**：①1/4 屏 = `cmd.Blit` 隐式视口残留 → 重写为手动全屏三角形（SV_VertexID 合成 3 顶点）+ 显式 SetViewport；②全白 = 材质实例默认 `_MainTex`（white）覆盖全局纹理 → 改材质实例显式绑定源 RT；③运行时 CopyTexture 报格式组错误 → 临时 RT 的 graphicsFormat 直接取源；④颠倒 = `1-uv.y` 翻转是 cmd.Blit 路径的遗留约定，全屏三角形下 uv 直传即正确 → 删除翻转。
- **R**：四轮全修，验收通过。收获是把"渲染链每一环的默认约定"（视口/纹理绑定/格式组/UV 朝向）全数踩了一遍并文档化。

### 故事 5：跨物体 Awake 顺序 NRE

- **S**：接入维度系统后 Play 刷屏 NullReference，栈指向对象池预热时子弹的 `MaskObject.OnEnable`。
- **T**：修复且不引入 Script Execution Order 这类全局配置。
- **A**：根因是 `WorldState.Instance` 在自己的 Awake 才赋值，而 Unity 跨物体 Awake 顺序未定义——池预热 Instantiate 出的子弹 OnEnable 可能先于 WorldState.Awake 执行。修复一行判空守卫；并做了防御纵深审计：全项目 19 处 Instance 读取点逐个检查，确认其余都在运行时点无裸读。
- **R**：NRE 消失。教训：**静态字段换组件单例读取时，"激活即读状态"的代码必须容错 Awake 顺序**。

### 故事 6：陷阱不致死——Kinematic↔Kinematic 无接触回调

- **S**：玩家接自研物理后，陷阱踩上去不死。
- **T/A**：排查发现陷阱和玩家事件总线都是 Kinematic 刚体，Unity 默认 **Kinematic↔Kinematic 不产生接触回调**——移除引擎驱动后这条隐式依赖暴露了。修复 `useFullKinematicContacts=true`，并补齐回调级维度门（异世界陷阱不可见也不可致死，替代被删掉的 IgnoreLayerCollision 语义）。
- **R**：陷阱恢复；方案 B（保留 Rigidbody2D 作事件总线）的语义就此补全。

### 故事 7（旧项目素材）：粘墙与"进不了下一关"

- **粘墙**（commit `97ff4f4`）：动态刚体时代角色蹭墙会被默认摩擦力粘住——给玩家挂零摩擦物理材质解决。STAR 里可以讲"物理材质是刚体手感的第一课"，并衔接后来自研物理彻底绕开这类引擎摩擦问题。
- **进不了下一关**（commit `e740ec0`）：RoomManager 是跨场景单例，却在 Awake 里缓存 Player 引用——第二次加载场景后引用指向已销毁对象，`EnterRoom` 静默失效。修复为懒获取 + `scene.IsValid()` 校验 + 空引用报错日志。可讲"单例生命周期 vs 场景对象生命周期"的经典错配。
- **相机**：每房间一台静态 CinemachineVirtualCamera，由 RoomManager 进房启用/退房禁用——坑在于 vcam 全部常开时 CinemachineBrain 会按 priority 乱切，禁用非当前相机后才稳定。

## 三、可能的追问与防线

- **"你的物理和 Box2D 比缺什么？"** → 诚实答：没有旋转/角动量、没有物理材质摩擦、没有连续碰撞检测（CCD 用 skinWidth+分轴迭代近似）。单人平台跳跃不需要这些，YAGNI。
- **"双人模式具体怎么改？"** → 过滤器按玩家实例注入（D3 已答）；WorldState 改为每玩家一份状态；显隐广播从静态事件改为按玩家订阅——静态事件是单人裁剪。
- **"顿帧为什么 timeScale=0 不卡转场？"** → 所有表现层过渡（Volume weight / 灯光交叉 / 转场进度 / 预览计时）统一用 `unscaledDeltaTime`。
- **"理智数值怎么定的？"** → 满 100、消耗 20/s（里世界上限 5s）、恢复 10/s、低于 30 禁止切入、L3 挑战段 ×2.5（预算 2s）。全部在 PlayerConfigSO/RoomConfigSO，可现场改数值演示。
- **"关卡怎么保证可复现？"** → 关卡由编辑器工具数据驱动生成（矩形/斜坡/特殊物列表），菜单一键重建，工具即设计文档。
